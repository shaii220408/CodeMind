# Architecture and data flow

CodeMind — AI-Powered Codebase Intelligence Platform has a React/Vite client, FastAPI API, Celery worker, Redis broker, PostgreSQL/pgvector database, and Google Gemini answer provider.

## Indexing

The authenticated upload route accepts ZIP files under `MAX_UPLOAD_MB`, saves them under the project upload directory, and queues a Celery job. The worker rejects unsafe archive paths and symlinks and enforces extracted-byte and file-count limits. It scans supported source extensions (Python, Java, JavaScript, TypeScript), skips known generated/vendor directories and large files, chunks source with line ranges, generates normalized 384-dimensional Sentence Transformers embeddings, and persists documents, chunks, heuristic dependencies, and graph rows in a database transaction. SHA-256 hashes skip unchanged document embeddings. Re-indexing updates the current rows; there are no retained index versions or atomic version promotion.

Tree-sitter grammars cover Python, Java, JavaScript and TypeScript. Chunk extraction remains symbol/line based; it is not full AST semantic extraction. The graph uses Python's standard-library AST plus Tree-sitter for Java/JavaScript/TypeScript. It stores file, module, class/interface, function/method, containment, import, call and recognized inheritance facts with source ranges. Calls and inheritance are linked only when a unique same-file declaration or a uniquely bound explicit local import is found; other references remain unresolved. This is static analysis and does not resolve dynamic dispatch, reflection, overload selection, or external packages.

Graph nodes and edges are project-scoped PostgreSQL rows with source paths/ranges and indexed relationship endpoints. Each upload reserves a monotonically increasing project generation. An indexing task locks the project row and skips stale generations before mutation; current graph rows are replaced from the full snapshot in the same transaction as documents and chunks. Duplicate deliveries serialize, failed transactions preserve the previous graph, and changed/deleted files are reflected on the next successful current snapshot.

Each successful complete index increments `projects.index_revision`. Review/health snapshots and generated Markdown are stored in `project_analyses` and `generated_documents`, keyed by project and revision. The review task reads the persisted current snapshot and applies deterministic rules and metrics; it does not call Gemini. Documentation generation reads indexed files and graph facts and replaces only documents for that revision. A project revision change makes older artifacts historical and the API serves only the current revision. These jobs are explicitly queued by an owner-scoped API request, so dashboard polling reads cached state rather than repeating expensive work. An older job marks its output stale when a newer successful revision exists.

The static review rules detect selected risky call patterns, credential-like literals (stored evidence redacted), TODO markers, approximate Python complexity, and repeated normalized source windows. This is a bounded heuristic analyzer, not a complete security scanner. Health reports indexed file/line and language counts, graph declaration counts, dependency hotspots, approximate Python complexity, duplicate windows, and review finding counts. It does not claim coverage without a coverage artifact. Documentation drafts include overview/setup, source modules, literal Python route decorators, and a Mermaid view of resolved graph relationships. Missing source facts are described as unavailable; README commands are quoted from the README rather than invented. Gemini is used only when a user explicitly asks to explain a finding, and that request contains the finding's redacted excerpt rather than repository-wide source.

The graph migration creates empty graph tables; already-indexed repositories are not backfilled automatically. Upload the repository snapshot again to populate graph rows for an existing project.

Graph impact defaults to direct callers and importers. The API can follow reverse resolved `calls` and `import` edges up to five levels, tracking visited entities to stop cycles. Returned transitive relationships include their hop depth. This remains a partial, static analysis: only unique locally resolved links are traversed, and dynamic dispatch and unresolved names are omitted.

## Question answering

`POST /api/ask` checks project ownership, combines PostgreSQL vector and lexical candidates using Reciprocal Rank Fusion, then applies a lexical-overlap score. Evidence below `MIN_RELEVANCE_SCORE` (0.45) is excluded. With a configured backend `GEMINI_API_KEY`, the server calls Gemini `generateContent` through Google's `google-genai` SDK. With no key, deterministic evidence fallback is used; if relevant evidence is insufficient, the answer abstains. Recent project conversation turns provide follow-up context but are explicitly distinguished from repository evidence. Provider errors remain HTTP service errors. Chat history stores retrieved evidence excerpts as well as answer mode and citations; the authenticated source endpoint serves only indexed file contents and validated line ranges.

Public GitHub projects can be created with a validated HTTPS repository URL and synchronized through Celery. Sync records branch, commit SHA and status. The worker downloads a bounded GitHub archive (no shell or git subprocess), checks the redirected host, enforces repository/archive/file/path limits, and safely extracts the snapshot. The existing project generation lock and single indexing transaction replace documents, chunks, dependencies and graph together; deleted and renamed paths disappear on successful sync. Failed indexing rolls back the snapshot update and retains the previous indexed state. Repeated syncs currently download full ZIP snapshots; file-level network transfer is not incremental. Only public repositories are supported. Private-repository support requires a backend-only GitHub App installation credential, scoped installation/repository permissions, encrypted secret storage/rotation and redacted audit; no token field is accepted today.

The API constructs citations from retrieved evidence and validates generated citation references against that evidence. The source endpoint also checks repository path ownership and bounds the requested line range.

## Runtime and operations

Compose binds service ports to loopback. The API readiness check probes PostgreSQL and Redis; the API container has a healthcheck. PostgreSQL and Redis also have healthchecks. The worker has no container healthcheck. Alembic migrations run at API startup. Prometheus metrics currently cover HTTP request counts and latency; structured JSON logs include audit events without request text or credentials.
